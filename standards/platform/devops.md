# DevOps / Platform / SRE Standards

Operational standards for deploying and running services: infrastructure-as-code, Kubernetes,
GitOps, secrets, observability, and reliability. Pipeline/supply-chain controls live in
[ci-cd.md](ci-cd.md) and [security.md](../practices/security.md); this is the **runtime/infra** layer.

> **Scope:** items tagged _(scale-up)_ are for teams running real production infra — adopt them
> as you grow, not on day one. The rest apply to any deployed service.

---

## 1. Infrastructure as Code

- **Standardize on one IaC tool** — **OpenTofu** (OSI-licensed, vendor-neutral fork; client-side
  state encryption) for greenfield, or Terraform where you need HashiCorp-only/HCP features. No
  console clickops; all infra is reviewable, versioned, reproducible.
- **Remote state with locking + encryption.** Prefer native S3 locking (`use_lockfile = true`,
  OpenTofu/Terraform 1.10+); **DynamoDB locking remains supported** (Terraform deprecated its
  `dynamodb_table` arg, OpenTofu has not); GCS has native locking. State holds plaintext
  secrets → KMS + bucket versioning + least-privilege IAM. One state per env/component; never
  commit state.
- **Pin everything; commit the lock.** `required_version`, provider `version` constraints,
  module git refs (`?ref=v1.4.2`), and `.terraform.lock.hcl` with multi-platform hashes.
- **CI gate:** `fmt -check` → `validate` → `tflint` → `plan` (posted to the PR) → **human-gated
  apply** (protected environments). Scan IaC with **Checkov** or **`trivy config`**
  (_tfsec is merged into Trivy and maintenance-only; Terrascan is archived — don't adopt either_);
  add **OPA/Conftest** for bespoke guardrails.
- **Secrets never in `.tf`/`.tfvars`/state.** `sensitive = true` only redacts logs — it does
  **not** encrypt state. Fetch at runtime via data sources (Secrets Manager/Vault) or inject via
  `TF_VAR_*`; SOPS+age for encrypted-at-rest config in git.
- **Environment separation = directory-per-env**, each with its own backend/state, calling shared
  versioned modules. HashiCorp's own guidance: CLI **workspaces are not suitable for permanent
  environments** — reserve them for ephemeral PR previews.

### 1.1 Modules, private registry & drift detection _(scale-up)_

- **Modules have a typed interface, not a junk drawer.** Every reusable module ships:

  | Element | Requirement |
  |---|---|
  | Inputs/outputs | Typed `variable`/`output` with `description` + `validation` blocks; mark `sensitive` |
  | Examples | `examples/<name>/` that `plan`s clean — doubles as smoke test |
  | Docs | `README.md` generated by **`terraform-docs`** (CI-checked, no drift) |
  | Versioning | **SemVer git tags** (`v1.4.2`); consumers pin `?ref=` / registry `version` |
  | Tests | **`terraform test`** (native, 1.6+) for fast assertions; **Terratest** for real apply/destroy E2E |

- **Publish to a private module registry** — don't `git clone` URLs across teams. Terraform Cloud/
  Enterprise registry, **Spacelift/Scalr/env0**, or a Git-tag-backed registry. Gives discoverability,
  versioned docs, and a single source of truth for the paved-road modules.
- **Drift detection is a scheduled job — GitOps selfHeal does NOT cover Terraform.** Argo/Flux
  reconcile k8s only; cloud infra mutated out-of-band (a console hotfix, an autoscaler, a teammate)
  drifts silently until the next `apply` surprises you. Run a **nightly `plan` against prod** in CI
  and **alert on any non-empty diff** (exit-code `2` from `plan -detailed-exitcode`), or use
  **driftctl / cloud-native drift detection** (TFC/Spacelift/env0 have it built-in). Reconcile drift
  via PR, never by hand.

## 2. Kubernetes _(scale-up)_

- **Requests/limits (the modern nuance):** always set **CPU + memory requests**. **Don't set CPU
  limits** on latency-sensitive services (throttles you below idle capacity for no gain); **set
  memory limit = memory request** (memory is non-compressible → OOMKilled). Right-size with
  VPA-recommender/Goldilocks.
- **Probes:** liveness restarts a wedged process, readiness gates traffic, startup covers slow
  boots. **Never check external deps (DB/downstream) in liveness** — a dep outage becomes a
  cluster-wide restart loop. Use a startup probe instead of a huge `initialDelaySeconds`.
- **`securityContext` hardening:** `runAsNonRoot`, `allowPrivilegeEscalation: false`,
  `readOnlyRootFilesystem: true`, `capabilities.drop: [ALL]`, `seccompProfile: RuntimeDefault`.
  Enforce namespace-wide with **Pod Security Admission** (`enforce: restricted`;
  _PodSecurityPolicy was removed in 1.25_); use **Kyverno/Gatekeeper** for policy beyond PSS.
- **Pin images by digest** (`image@sha256:…`), never `:latest` — enforce with Kyverno/Gatekeeper.
- **Verify signatures at admission — close the supply-chain loop.** [security.md](../practices/security.md)
  says CI signs images (keyless cosign); admission control must actually *check* it. Kyverno
  `verifyImages` with the **keyless `subject`/`issuer`** identity pins images to *your* CI workflow —
  an unsigned or foreign-built image never schedules. Kyverno also mutates the tag → digest it
  verified, so pinning + verification are one step:

  ```yaml
  apiVersion: kyverno.io/v1
  kind: ClusterPolicy
  metadata: { name: verify-image-signatures }
  spec:
    validationFailureAction: Enforce      # block, don't just audit
    webhookTimeoutSeconds: 30
    rules:
      - name: verify-cosign-keyless
        match: { any: [{ resources: { kinds: [Pod] } }] }
        verifyImages:
          - imageReferences: ["ghcr.io/acme/*"]
            mutateDigest: true            # pin tag→digest on the verified image
            attestors:
              - entries:
                  - keyless:
                      subject: "https://github.com/acme/*/.github/workflows/*@refs/heads/main"
                      issuer: "https://token.actions.githubusercontent.com"
                      rekor: { url: "https://rekor.sigstore.dev" }
  ```
- **Lint manifests in CI:** **kubeconform -strict** (schema) + **kube-linter** (best-practice/
  security) → `kubectl apply --dry-run=server`. _(kubeval/datree are unmaintained — don't adopt.)_
- **Templating contract:** **Helm** for third-party charts and anything needing `helm rollback`;
  **Kustomize** for your own apps (base + per-env overlays). Don't blur the two.
- Standard `app.kubernetes.io/*` labels on every object (name/instance/version/component/
  part-of/managed-by) — they drive selectors, dashboards, cost allocation, PDB/NetworkPolicy.
- _(scale-up)_ PodDisruptionBudgets for HA, ResourceQuota+LimitRange per namespace, and a
  **default-deny NetworkPolicy** (always allow DNS egress) on a policy-capable CNI (Cilium/Calico).

## 3. GitOps & deployment _(scale-up)_

- **Git is the source of truth; a controller reconciles.** Default to **Argo CD** (UI, drift
  visualization) — Flux for CLI/CRD-only platforms; both are CNCF-graduated. Enable
  `syncPolicy.automated: { prune: true, selfHeal: true }`.
- **Promotion is a PR**, never a manual `kubectl`. Dev/staging auto-sync; **prod gated behind a
  merged PR**. Argo ApplicationSet (env-per-folder) at scale.
- **Decouple deploy from release** with feature flags (**OpenFeature** — vendor-neutral SDKs):
  rollback becomes a config toggle, not a redeploy.
- **Progressive delivery** with metric-gated auto-rollback: **Argo Rollouts** (with Argo CD) or
  **Flagger** (with Flux) — canary steps gated on an `AnalysisTemplate`, auto-revert on breach.
  See §3.1.
- **Database migrations are expand/contract.** Rolling/canary means two app versions run at once,
  so every change must be **N-1 compatible**: add-new → dual-write/backfill → switch reads → drop-
  old (in a later release). Lint destructive changes (`atlas migrate lint`). See
  [database.md](database.md).

### 3.1 Progressive delivery: gate on your golden signals _(scale-up)_

The whole point is that **the AnalysisTemplate's inputs ARE your §6 golden signals / §7 SLOs** —
the canary is auto-rolled-back the instant it would burn error budget, comparing canary against the
stable baseline:

```yaml
# Rollout: shift weight in steps, run analysis in the background
spec:
  strategy:
    canary:
      analysis:                          # background analysis across all steps
        templates: [{ templateName: golden-signals }]
        args: [{ name: service, value: checkout }]
      steps:
        - setWeight: 10
        - pause: { duration: 5m }
        - setWeight: 30
        - pause: { duration: 10m }
        - setWeight: 60
        - pause: { duration: 10m }
        - setWeight: 100
---
apiVersion: argoproj.io/v1alpha1
kind: AnalysisTemplate
metadata: { name: golden-signals }
spec:
  args: [{ name: service }]
  metrics:
    - name: error-rate
      interval: 1m
      failureLimit: 2                     # 3rd breach → Failed → abort
      provider:
        prometheus:
          address: http://prometheus.monitoring:9090
          # canary 5xx ratio — same query that backs the SLO burn-rate alert
          query: |
            sum(rate(http_requests_total{service="{{args.service}}",
                     role="canary",code=~"5.."}[2m]))
            / sum(rate(http_requests_total{service="{{args.service}}",role="canary"}[2m]))
      successCondition: result < 0.01     # <1% errors (the SLO threshold)
    - name: latency-p99
      interval: 1m
      provider:
        prometheus:
          address: http://prometheus.monitoring:9090
          query: |
            histogram_quantile(0.99, sum(rate(
              http_request_duration_seconds_bucket{service="{{args.service}}",role="canary"}[2m]
            )) by (le))
      successCondition: result < 0.3      # p99 < 300ms latency objective
```

- **Baseline-vs-canary**, not absolute thresholds where you can: a noisy-neighbour spike that hits
  both versions shouldn't fail the rollout — compare canary metrics against the stable `role` label.
- **Abort = auto-rollback to zero weight.** On `failureLimit` breach Argo Rollouts aborts, drops the
  canary to 0%, and holds — it does **not** auto-promote on a degraded signal. Pair with §3 feature
  flags so a bad release is a flag-off, not a re-roll.

## 4. Secrets at runtime

- **No plaintext in git — non-negotiable.** Pick per context: **External Secrets Operator + a
  cloud secret manager** (the trending default for multi-cluster GitOps), **SOPS+age** (the only
  truly platform-agnostic file encryption), **Sealed Secrets** (simple, cluster-locked), or
  **Vault** (dynamic secrets). Pair with **rotation** — no long-lived static secrets.
- See [security.md](../practices/security.md) for the full secrets posture.

## 5. Identity & network

- **Least-privilege IAM via OIDC / workload identity** — short-lived federated creds, not static
  keys (the #1 cloud-breach vector). EKS Pod Identity/IRSA, GCP Workload Identity Federation,
  GitHub Actions OIDC (pin the trust policy `sub` to your repo/ref). See [ci-cd.md](ci-cd.md) §OIDC.
- **TLS everywhere**, automated via **cert-manager** (validate against Let's Encrypt staging
  first; DNS-01 for wildcards). mTLS via a service mesh _(scale-up)_.

## 6. Backups & disaster recovery _(scale-up)_

A backup in the **same account and region as prod is not DR** — one compromised IAM principal, one
ransomware event, or one region outage takes prod and its "backup" together. DR is about surviving a
**blast radius**, not a dropped table.

- **Set RTO/RPO per tier** (not one blanket number) and design backups to hit them:

  | Tier | Example | RTO | RPO | Mechanism |
  |---|---|---|---|---|
  | 0 — critical | payments, auth | < 1h | ~0 (near-zero loss) | DB **PITR** + sync/standby replica; multi-region |
  | 1 — core | primary app/API | < 4h | ≤ 15m | PITR + cross-region snapshot copy |
  | 2 — supporting | internal tools | < 24h | ≤ 24h | Nightly snapshot, cross-region copy |
  | 3 — rebuildable | caches, derived data | best-effort | n/a | Recreate from source/IaC |

- **Match the backup *scope* to the data:**
  - **Databases → PITR** (continuous WAL/binlog + base backup), not just nightly dumps — a dump loses
    a day; PITR recovers to the second before the incident.
  - **Stateful volumes → snapshots** (EBS/PD/CSI `VolumeSnapshot`); app-consistent (quiesce/freeze)
    where possible, not just crash-consistent.
  - **Object storage → versioning + lifecycle** so an overwrite/delete is recoverable.
- **Cross-region + cross-account copy** is the line between backup and DR. Replicate snapshots and
  object data to a **separate region** (region outage) **and a separate account/project/subscription**
  with its own credentials (ransomware / insider / compromised-prod-account blast radius). The DR
  account's restore role must **not** be assumable from prod.
- **Immutable / WORM backups.** Enable **S3 Object Lock (Compliance mode)** / Azure immutable blob /
  GCS retention-lock so backups **cannot be deleted or encrypted even by an admin or attacker** for
  the retention window — the single highest-value control against ransomware.
- **Encrypt every backup** with a KMS key (ideally a **separate DR-account key**); restores must be
  tested under that key, not prod's.
- **Test restores on a schedule or it's theatre.** A backup you've never restored has an unknown RTO.

  ```text
  Restore runbook (gated: runs monthly in CI, fails the check if skipped or over RTO)
  1. Provision target in the DR account/region from IaC (clean room, prod creds denied)
  2. Restore DB to a PITR timestamp; restore volumes from the latest cross-region snapshot
  3. Run app smoke + data-integrity checks (row counts, checksums, latest-write present)
  4. Record wall-clock restore time → compare to tier RTO; record recovery point → vs RPO
  5. Alert + file an action item if RTO/RPO missed or the drill didn't run
  ```

- Follow **3-2-1** (3 copies, 2 media, 1 off-site/off-account) as the baseline shape.

## 7. Observability

Canonical home: **[observability.md](observability.md)** — the full signal model, instrumentation,
sampling, and SLO/alerting policy. This section is the deploy/run summary.

- **Metrics:** Prometheus + Grafana + Alertmanager (CNCF-graduated). Measure with **RED**
  (request rate/errors/duration for services) + **USE** (utilization/saturation/errors for
  resources); track the **four golden signals** for user-facing health.
- **Traces/logs:** **OpenTelemetry** over OTLP — instrument once, swap backends. **Structured JSON
  logs** with `trace_id`/`span_id` and a correlation ID threaded from the edge; required fields:
  `timestamp` (ISO-8601 UTC), `level`, `service`, `trace_id`, `message`. Logs → Loki (cost) or
  OpenSearch (full-text).
- **Alert on symptoms, not causes.** Page on **SLO multi-window, multi-burn-rate** signals — never
  raw CPU. Every page must be actionable and link a runbook.
- **Health vs readiness endpoints** are distinct (`/healthz` = process; `/readyz` = dependencies).

## 8. Reliability (SRE) _(scale-up)_

- **SLOs + an error-budget policy** (a written doc: "budget exhausted → freeze releases except
  P0/security") — the error budget is the shared currency between velocity and stability. Rolling
  4-week window; generate Prometheus rules with Sloth/OpenSLO.
- **Runbooks** are version-controlled, linked from alert annotations.
- **Blameless postmortems** for SEV-1/2 (or >20% budget burn) with owned, dated action items.
- **On-call:** tiered escalation with timeouts; every alert actionable; track alerts-per-shift.

## 9. Capacity & multi-region _(scale-up)_

- **Autoscale on demand, keep headroom for the spike you can't predict.** **HPA** (or **KEDA** for
  event/queue-driven scaling — Kafka lag, SQS depth, cron) scales pods; the **cluster-autoscaler**
  (or **Karpenter**) scales nodes. Keep **headroom** so a scale-up isn't gated on cold node boot —
  size HPA target utilization with slack, and run **low-priority pause Pods** (over-provisioning)
  so urgent pods preempt instantly instead of waiting minutes for a new node.
- **Never run HPA and VPA on the same metric** — they fight: VPA resizes requests while HPA scales
  on utilization of those same requests, oscillating. Run **VPA in recommender-only mode** to
  right-size requests, and let **HPA own scaling**. (Or VPA for the one-replica/stateful workloads
  HPA can't help.)
- **PDB + surge math must leave capacity to serve.** A `PodDisruptionBudget` (`minAvailable`) caps
  voluntary disruption (drains, rollouts) so an upgrade can't evict your whole service; size it with
  the rollout surge (`maxUnavailable`/`maxSurge`) so `replicas − maxUnavailable ≥ minAvailable` and
  the survivors can carry peak load. PDBs **don't** protect against node *failure* — only voluntary
  evictions.
- **Multi-region posture** is an RTO decision, not a checkbox:

  | Posture | RTO | Cost/complexity | Data model |
  |---|---|---|---|
  | **Active-passive** (warm standby) | minutes–1h (failover) | lower | async replication → bounded data-loss window (RPO > 0) |
  | **Active-active** | ~0 (just shift traffic) | high | needs conflict resolution / global DB or sync quorum |

  Front both with a **global load balancer + health-checked DNS/anycast failover** (Route 53 /
  Cloud DNS / Cloudflare). The hard part is always **data**: synchronous replication buys RPO≈0 at a
  latency/throughput cost; asynchronous is cheap but accepts a loss window — pick per [database.md](database.md)
  and the §6 tier RTO/RPO table, and **rehearse the regional failover** like any other restore.

## 10. Environments, config & cost

- **Dev/staging/prod parity:** the **same container image** everywhere (only env vars/config
  differ); all infra in version-controlled IaC; pin backing-service versions.
- **12-factor config**: config separate from code, no secrets in VCS, `.env.example` committed.
  (Don't dogmatically mandate env-vars-only — mounted secret files are fine and often preferred.)
- _(scale-up)_ **Cost hygiene:** a mandatory tag schema (`owner`/`team`/`env`/`service`/
  `cost-center`) stamped via IaC `default_tags`; **Infracost** posting `+$/mo` on PRs; anomaly
  alerts. Start with showback before chargeback.
- _(scale-up)_ **k6** load tests as a CI gate (thresholds fail the build); graduate to chaos
  engineering once SLOs/observability are mature.

## 11. Platform engineering & golden paths _(scale-up)_

- **Build a paved road, not a maze of options.** A golden path is the **supported, opinionated,
  self-service** way to ship a service — repo scaffold, CI, deploy manifests, dashboards, and
  on-call wiring generated for you. Teams move faster *and* land on the secure default because
  the easy path is the right path.
- **Scaffold from templates, don't copy-paste.** Templated service generators — **Backstage
  software templates**, **cookiecutter/`copier`**, or a `create-service` CLI — emit a new service
  pre-wired to every standard here (digest-pinned base image, hardened `securityContext`, probes,
  OTel, golden-signal dashboards, GitOps app). A **self-service catalog** (Backstage, or a simple
  internal portal) makes them discoverable and tracks ownership.
- **These standards _are_ the paved road.** The default is to follow them; **deviation is allowed
  but must be justified** (a short ADR / exception record, not silent drift). The paved road earns
  adoption by being genuinely easier — invest in the templates so opting out is the expensive
  choice, never the cheap one.

## Definition of done

- [ ] All infra is IaC; remote state locked + encrypted; lockfile committed; secrets out of state
- [ ] IaC CI: fmt/validate/lint/scan + plan-on-PR + gated apply
- [ ] _(scale-up)_ Reusable modules: typed interface, examples, `terraform-docs` README, SemVer,
      tests, published to a private registry; **scheduled `plan` drift-detection alerts**
- [ ] Workloads: requests set (no CPU limit, memory limit = request); correct probes; hardened
      `securityContext`; digest-pinned images; manifests linted
- [ ] Image signatures **verified at admission** (Kyverno `verifyImages`, keyless subject/issuer)
- [ ] Deploys are GitOps + PR-promoted; releases decoupled via flags; migrations are N-1 safe
- [ ] _(scale-up)_ Progressive delivery: canary `AnalysisTemplate` gated on golden-signal/SLO
      queries; baseline-vs-canary; auto-rollback on breach
- [ ] No plaintext secrets; rotation in place; cloud auth via OIDC
- [ ] _(scale-up)_ DR: per-tier RTO/RPO; backups scoped (PITR/snapshots/versioning);
      **cross-region + cross-account**, immutable/WORM, encrypted; **scheduled tested-restore** drill
- [ ] _(scale-up)_ Capacity: HPA/KEDA + autoscaler headroom (no HPA+VPA on one metric); PDB + surge
      math; multi-region posture chosen against tier RTO/RPO
- [ ] Metrics (RED/USE) + OTel traces + structured correlated logs; symptom-based SLO alerts
- [ ] SLOs + error-budget policy + runbooks + blameless postmortems _(scale-up)_
- [ ] _(scale-up)_ Golden-path scaffold/catalog exists; deviations from these standards are justified
