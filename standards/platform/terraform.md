# Terraform / OpenTofu (IaC) Standards

How we write, review, and ship infrastructure-as-code. [devops.md](./devops.md) summarizes IaC as
one layer of the runtime/platform story and **defers the depth to this doc**; the pipeline wiring
lives in [ci-cd.md](./ci-cd.md), secrets/scanning rationale in
[../practices/security.md](../practices/security.md), and version-pinning policy in
[../practices/dependencies.md](../practices/dependencies.md). This file is the canonical IaC home.

> **One law:** every change to infrastructure is a reviewed, planned, version-pinned diff — never a
> console click and never an `apply` from a laptop.

---

## 1. Toolchain

Default to **OpenTofu**; reach for Terraform only when you need a HashiCorp-only feature.

| Concern | Tool | Notes |
|---|---|---|
| IaC engine | **OpenTofu** (≥ 1.8) | OSI-licensed, vendor-neutral fork; **client-side state encryption** built in. Terraform is the *escape hatch* — use it for HCP/TFC-only features (Stacks, no-code modules), and document why |
| Format / validate | `tofu fmt` · `tofu validate` | formatting is non-negotiable; `validate` catches HCL/type errors offline |
| Lint | **TFLint** (+ cloud ruleset) | deprecated args, invalid instance types, naming, unpinned sources |
| Security scan | **Checkov** or **`trivy config`** | misconfig/policy scan; _tfsec is merged into Trivy and maintenance-only — don't adopt it standalone_ |
| Docs | **terraform-docs** | CI-checked module README; no drift between inputs and docs |
| Test | **`tofu test`** (native) + **Terratest** _(scale-up)_ | fast assertions in-repo; real apply/destroy E2E in Go |

## 2. Everyday commands

```bash
tofu fmt -recursive            # format every .tf in the tree
tofu validate                  # offline: HCL + type + provider schema
tflint --recursive             # CI runs this
checkov -d . --quiet           # or: trivy config .
tofu plan -out=plan.tfplan     # CI posts this to the PR; humans read it
tofu apply plan.tfplan         # gated, runs only in CI on the merged commit
```

CI runs `fmt -check`, `validate`, `tflint`, the security scan, and `plan` on every PR; `apply` is
a separate, environment-gated job. **Never `apply` from a developer machine** — see §5.

## 3. Project & module structure

- **Directory-per-environment root modules.** Each env (`envs/dev`, `envs/staging`, `envs/prod`)
  is its own root module with its **own backend/state**, calling shared versioned child modules.
  This isolates blast radius and lets prod lag dev on a module version deliberately.

  ```text
  infra/
    modules/                 # reusable child modules (the paved road)
      network/               # variables.tf · outputs.tf · main.tf · README.md · examples/
      service/
    envs/
      dev/      { backend.tf · main.tf · terraform.tfvars }   # own state
      staging/  { backend.tf · main.tf · terraform.tfvars }   # own state
      prod/     { backend.tf · main.tf · terraform.tfvars }   # own state
  ```

- **CLI workspaces are NOT environments.** HashiCorp's own guidance: workspaces share one backend
  and are unsuitable for permanent envs — reserve them for **ephemeral PR previews** that share a
  config. Directory-per-env is the durable pattern.
- **No copy-paste between envs.** If two envs differ only in inputs, they call the *same* child
  module with different `tfvars` — duplicated resource blocks drift silently. Factor the shared
  shape into a module the moment you'd copy it a second time (but see §10 — don't over-abstract).
- **Modules have a typed interface, not a junk drawer:**

  | Element | Requirement |
  |---|---|
  | Inputs/outputs | Typed `variable`/`output` with `description` + `validation`; mark `sensitive = true` |
  | Examples | `examples/<name>/` that `plan`s clean — doubles as a smoke test |
  | Docs | `README.md` generated by **terraform-docs**, CI-checked for drift |
  | Versioning | **SemVer git tags** (`v1.4.2`); consumers pin `?ref=` or a registry `version` |

- **Publish shared modules to a private registry** _(scale-up)_ — TFC/Enterprise, Spacelift/Scalr/
  env0, or a Git-tag-backed registry — don't `git clone` URLs across teams.

## 4. State

- **Remote backend, always.** S3 / GCS / Azure Blob — never local state, never state in git.
- **Prefer native locking.** Native S3 `use_lockfile = true` (OpenTofu 1.10+ / Terraform 1.10+)
  is preferred; GCS and Azure lock natively. **DynamoDB locking remains supported** — OpenTofu has
  not deprecated it (only Terraform deprecated its `dynamodb_table` arg) — but native `use_lockfile`
  is the greenfield default.
- **Encrypt at rest *and* in the statefile.** Bucket SSE (KMS) + versioning covers at-rest;
  OpenTofu **state encryption** (a `terraform { encryption { … } }` block, e.g. AWS KMS or PBKDF2
  passphrase key provider) encrypts the state body itself so a leaked bucket object is ciphertext.

  ```hcl
  terraform {
    encryption {
      key_provider "aws_kms" "state" { kms_key_id = var.state_kms_key_arn }
      method "aes_gcm" "default" { keys = key_provider.aws_kms.state }
      state { method = method.aes_gcm.default }
      plan  { method = method.aes_gcm.default }
    }
  }
  ```

- **State holds plaintext secrets — treat it as a secret.** Every `sensitive = true` value, every
  generated password, every data-source read lands in state in cleartext. Least-privilege IAM on
  the backend bucket; never print state; never commit it.
- **Segment state by env *and* by blast radius.** One state per env per component (network /
  data / app), not one mega-state for the whole account. Small states = faster plans, smaller
  lock contention, and a bounded blast radius when an `apply` goes wrong. Cross-reference via
  `terraform_remote_state` data sources or published outputs, not by merging states.

## 5. The workflow

The pipeline is the only thing allowed to mutate infrastructure. Gates, in order:

| Stage | Command | Gate |
|---|---|---|
| Format | `tofu fmt -check -recursive` | fails on unformatted HCL |
| Validate | `tofu validate` | fails on type/schema errors |
| Lint | `tflint --recursive` | fails on deprecated/invalid/unpinned |
| Security scan | `checkov -d .` / `trivy config .` | fails on misconfig at chosen severity |
| Policy | `conftest test` (OPA) — see §7 | fails on a guardrail breach |
| Plan | `tofu plan -out=plan.tfplan` | **posted to the PR**; humans read the diff |
| Apply | `tofu apply plan.tfplan` | **human-gated, protected environment, CI only** |

- **Never `apply` from a laptop.** Local creds bypass review, plan-posting, and the audit trail.
  `apply` runs only in CI, on the merged commit, against the exact plan the reviewer approved.
- **Apply the saved plan, not a fresh one.** `apply plan.tfplan` guarantees what merged is what
  ships; a re-plan at apply time can drift from what was reviewed.
- **CI auth via OIDC, not static keys.** Mint short-lived federated credentials per run (GitHub
  Actions OIDC → AWS/GCP/Azure); pin the trust policy `sub` to your repo/ref. Long-lived cloud
  keys in CI secrets are the #1 cloud-breach vector. Full wiring in [ci-cd.md](./ci-cd.md) §OIDC.
- **Protected environments gate prod.** Required reviewers + a deployment-branch policy on the
  `prod` apply job (see [ci-cd.md](./ci-cd.md) §Environments).

## 6. Secrets

- **Never in `.tf`, `.tfvars`, or state.** `sensitive = true` only **redacts logs — it does not
  encrypt state** (§4). A secret in a committed `tfvars` is a leaked secret.
- **Fetch at runtime via data sources.** Read from AWS Secrets Manager / GCP Secret Manager /
  Vault at plan/apply time, or inject via `TF_VAR_*` from the CI secret store — the value lives in
  the secret manager, IaC only references it.

  ```hcl
  data "aws_secretsmanager_secret_version" "db" { secret_id = "prod/db/password" }
  resource "aws_db_instance" "main" {
    password = data.aws_secretsmanager_secret_version.db.secret_string   # never a literal
  }
  ```

- **Prefer not materializing secrets at all** — IAM/workload-identity auth and provider-managed
  passwords (`manage_master_user_password`) keep the value out of your state entirely.
- **SOPS+age** for encrypted-at-rest config that genuinely must live in git. Full secrets posture:
  [../practices/security.md](../practices/security.md) §7.

## 7. Policy as code

Scanners (§5) catch *known* misconfigs; policy-as-code enforces *your* rules ("every bucket is
KMS-encrypted", "no `0.0.0.0/0` ingress", "mandatory cost tags").

- **OPA + Conftest** (default, vendor-neutral) — Rego policies run against the `plan` JSON
  (`tofu show -json plan.tfplan | conftest test -`) as a CI gate. Portable across OpenTofu and
  Terraform.
- **Sentinel** only inside the HashiCorp ecosystem (TFC/Enterprise) — it's the Terraform escape
  hatch's policy engine, not a greenfield choice.
- **Gate on the plan, not the source.** Evaluating the planned diff catches what a resource will
  *actually* become (including module-injected defaults), which source-only linting misses.

## 8. Drift detection

- **GitOps selfHeal does NOT cover Terraform** — Argo/Flux reconcile Kubernetes only. Cloud infra
  mutated out-of-band (a console hotfix, an autoscaler, a teammate) drifts silently until the next
  `apply` surprises you.
- **Run a scheduled `plan` against prod** _(scale-up)_ in CI and **alert on any non-empty diff**
  (exit code `2` from `plan -detailed-exitcode`), or use built-in drift detection
  (TFC/Spacelift/env0) or **driftctl**. Reconcile drift via a PR, never by hand.

## 9. Testing

- **`tofu test`** (native) for fast assertions — input validation, computed outputs, conditional
  logic — using `command = plan` mocks where you don't want real resources.

  ```hcl
  # tests/network.tftest.hcl
  run "valid_cidr" {
    command = plan
    variables { cidr = "10.0.0.0/16" }
    assert {
      condition     = aws_vpc.main.cidr_block == "10.0.0.0/16"
      error_message = "VPC CIDR did not match the input"
    }
  }
  ```

- **Terratest** _(scale-up)_ for real apply/destroy E2E on every reusable module — it provisions,
  asserts against the live API, and tears down. Run it on a schedule (it costs real money/time),
  not on every PR.
- **`examples/` that `plan` clean** are the cheapest smoke test — wire them into CI (§3).

## 10. DRY without over-abstraction

- **Abstract on the second copy, not the first.** A module that wraps a single resource to "stay
  DRY" adds indirection for no reuse. Factor a module when a shape is genuinely shared across
  envs/services; otherwise plain `tfvars` differences are clearer than a parameter-explosion module.
- **Terragrunt is for scale, not day one** _(scale-up)_. Reach for it when directory-per-env
  backend/provider boilerplate becomes real duplication across many envs/accounts — it keeps
  backends and inputs DRY and runs dependency-ordered applies. A handful of envs don't need it;
  native OpenTofu plus a thin CI wrapper is simpler. (OpenTofu's own `terraform` block and
  variable defaults now cover much of what once needed Terragrunt.)

## Definition of done

- [ ] **OpenTofu** by default; any Terraform use is the documented escape hatch
- [ ] Directory-per-env root modules, each with **its own backend/state**; shared logic is a
      versioned child module, not copy-paste; workspaces only for ephemeral previews
- [ ] Reusable modules have a typed interface, `validation`, `examples/`, terraform-docs README,
      and SemVer tags _(scale-up: published to a private registry)_
- [ ] Remote state with **native locking** (prefer `use_lockfile`; DynamoDB still supported),
      bucket KMS + versioning, **state encryption** on; state segmented per env/component;
      **never committed**
- [ ] Providers/modules version-pinned and **`.terraform.lock.hcl` committed** with multi-platform
      hashes (see [../practices/dependencies.md](../practices/dependencies.md))
- [ ] CI gates: `fmt -check` → `validate` → `tflint` → **scan (Checkov/`trivy config`)** →
      **policy (Conftest/OPA)** → **plan-on-PR** → **human-gated apply** (applies the saved plan)
- [ ] **No `apply` from a laptop**; prod apply behind a protected environment; **CI auth via OIDC**,
      no long-lived cloud keys
- [ ] **Secrets never in `.tf`/`.tfvars`/state** — fetched via data sources / `TF_VAR_*`;
      `sensitive` understood as log-redaction only
- [ ] _(scale-up)_ Scheduled `plan` **drift-detection** alerts on prod; drift reconciled via PR
- [ ] Modules covered by **`tofu test`**; reusable modules have **Terratest** E2E _(scale-up)_
- [ ] No premature abstraction; **Terragrunt** only when env boilerplate is real duplication
      _(scale-up)_
